Chapter 3 Exercises ~35 min, hands-on

Exercises: Direct Prompt Injection

These exercises use a new scenario, deliberately different from the lesson's Meridian Notes / Concierge example: HelixCare Intake, a fictional telehealth pre-visit intake assistant with one tool that has a real side effect, schedule_appointment(patient_id, slot). You'll classify five real injection attempts by technique family, predict how a naive keyword filter behaves against each, and design real defenses — not just recall the lesson's taxonomy names.

Exercise standard Eight tasks total. Five are marked production-gear — defense evaluation, defense-in-depth reasoning, bounded-consequence design, provider-guidance matching, and a full defense-layer completeness gate, not just concept recall.
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect 24/24.
starter.py solution.py (reference)

1 Classify technique families

Match five HelixCare Intake injection attempts to the correct technique family from this chapter's taxonomy — role-play, instruction override, context confusion, obfuscation, or multi-turn escalation.

2 Predict keyword-filter behavior

For the same five attempts, predict whether a naive filter blocking "ignore"/"disregard"/"override" would actually catch each one — the exercise that makes payload obfuscation's real weakness concrete.

3 Production-gear Evaluate candidate defenses

Given four candidate fixes for HelixCare Intake, decide which ones actually reduce direct-injection risk or its consequences versus which are unrelated UX changes.

4 Production-gear Defense-in-depth reasoning

Write a real, justified sentence explaining why keyword filtering alone isn't sufficient — naming both a specific weakness and what to add alongside it.

5 Production-gear Bounded-consequence rule design

Design one concrete, code-enforced rule for schedule_appointment that would still stop a successful injection from booking an inappropriate appointment.

6 Provider guidance matching

Match two documented defense descriptions to the real provider (OpenAI or Anthropic) whose published guidance this chapter cites for each.

7 Multi-turn escalation detection

Decide whether a given three-turn transcript demonstrates gradual escalation or is a benign, non-escalating exchange — a judgment call, not a keyword match.

8 Production-gear Defense-layer completeness gate

Confirm all four of this chapter's defense layers were at least considered while working through Exercises 1–7 — the same completeness discipline Chapter 2's Step 6 required for OWASP categories.
