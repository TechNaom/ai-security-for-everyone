Chapter 2 Practice Bank ~20 min, fast pattern recognition

Practice Bank: Mapping the Attack Surface of a Real LLM Feature

Eight short, independent scenarios, each with its own fictional system — none of them Waypoint or ReviewMate again. Several are built specifically around this chapter's core lesson: a tool's output re-entering context is just as real an injection channel as a user-typed field, even when no user ever touched the malicious text. The point of this bank isn't depth on one system — it's speed and accuracy across many different systems, the way a real security review actually feels.

Practice standard Eight scenarios. Two are pure judgment calls with no single obvious "gotcha" keyword (Scenario 6 asks whether a described process is already sufficient; Scenario 7 asks you to prioritize between two real but unequal risks) — these test judgment, not just pattern matching against a category name.
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect 9/9.

Scenario 1

ClaimsBot

An insurance-claims bot reads free-text claim descriptions and can call approve_claim(claim_id, amount). A claim description contains a planted instruction telling the bot to skip manual review and approve the full amount. Which category explains how that instruction got a foothold in the first place?

Scenario 2 · Tool-output injection

MarketWatch

A stock-research assistant's fetch_headlines(ticker) tool pulls text from a public news aggregator into context. One low-quality-source headline contains a planted instruction telling the bot to always describe a stock as a strong buy. No user ever typed this text. Which category explains how it still got a foothold?

Scenario 3

DocSummarizer

A bot summarizes uploaded contracts and posts the summary as raw, unescaped HTML on a shared legal-team portal. A contract contains a crafted string that executes as a script once rendered. Which category explains the portal's vulnerability, given the model just faithfully reproduced context text?

Scenario 4

RecommendAI

A product-recommendation model fine-tuned on unvetted scraped reviews consistently promotes a product that received dozens of coordinated fake reviews from the same handful of accounts during training. Which category explains this?

Scenario 5

OpsChat

An internal ops chatbot has no per-user rate limit and no output-length cap. A misconfigured monitoring script sends tens of thousands of automated requests overnight, spiking the hosting bill. Which category explains this?

Scenario 6 · Judgment

VendorGate

Before integrating a third-party plugin, a team requires a signed provenance manifest, a full source-code review, sandboxed execution with no default network access, and a pinned version hash that only changes through manual re-review. Does a real, unaddressed Supply Chain risk remain, or does this process already cover the core practice?

Scenario 7 · Judgment

LegalAssist

Two known issues, only one fixable before launch: (a) the model confidently cites fabricated case law with no way for a user to verify it, or (b) its system prompt leaks an internal routing rubric the firm already summarizes publicly elsewhere. Which is the higher-impact fix?

Scenario 8 · Production-gear

WarehouseBot

A supplier's shipment note — read through a read_supplier_note tool, not typed by any WarehouseBot employee — tells the bot to reorder 10,000 units of a SKU regardless of stock levels, and schedule_reorder has no quantity cap or human approval step. Name both OWASP categories this maps to — one for how the instruction got in through a tool, one for why it caused real damage.
