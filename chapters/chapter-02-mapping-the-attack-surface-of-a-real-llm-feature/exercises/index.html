Chapter 2 Exercises ~35 min, hands-on

Exercises: Mapping the Attack Surface of a Real LLM Feature

These exercises use a second scenario, deliberately different from the lesson's Waypoint trip-planning assistant: ReviewMate, a fictional internal code-review assistant that reads pull requests, linked issues, and CI logs, and can post comments and merge PRs, with tools including read_pr_diff, read_linked_issue, get_ci_logs, post_comment, and merge_pr. Applying the systematic method to a fresh scenario is the point; recalling the lesson's answers by heart won't get you through these.

Exercise standard Eight tasks total. Five are marked production-gear — they involve access/permissions review, risk evaluation, output-rendering safety, cost controls, and a compliance completeness gate, not just concept recall.
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect 31/31.
starter.py solution.py (reference)

1 Map assets to OWASP categories

Assign the correct OWASP Top 10 for LLM Applications category ID (e.g. LLM01) to five ReviewMate attack-surface descriptions — the PR description text, the CI log output, the overscoped merge tool, the leaky system prompt, and the overscoped issue-tracker lookup.

2 Trust classification

For four inputs that reach ReviewMate's context window, decide which are trusted (operator-authored) and which are untrusted (attacker-influenceable) — the same distinction the lesson's Step 3 draws.

3 Production-gear Evaluate Excessive Agency fixes

Given four candidate fixes for the merge_pr tool, decide which ones actually reduce Excessive Agency risk (requiring a second human approval, restricting scope to low-risk paths) versus which are unrelated reliability/UX changes.

4 Likelihood/impact reasoning

Write a real, justified sentence — not a bare "high" or "low" — explaining both how easily an attacker reaches the PR-description asset and what happens if they do.

5 Production-gear Output handling

ReviewMate posts comments as markdown, where images and links can render or auto-load without a click. Name the OWASP category this maps to and one concrete mitigation.

6 Production-gear Unbounded consumption

ReviewMate can be asked, via PR text, to trigger CI reruns with no per-PR or per-day cap. Name the OWASP category this maps to and one concrete mitigation.

7 Production-gear System prompt leakage compliance check

Decide whether embedding the exact auto-merge safety criteria in the system prompt is a real compliance problem, and name the fix that moves it out of the "trust the model to follow this" layer.

8 Production-gear Full-framework completeness check

Confirm all 10 OWASP categories were at least considered while working through Exercises 1–7 — the same completeness gate Section 6's Step 6 requires before a threat model ships to production.
