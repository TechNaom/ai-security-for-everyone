Chapter 2 Project ~90 min, hands-on Level 1 · Guided

Project: Threat-Model AskHR End to End

This is Module 1's real Level 1 (Guided) project, per the course's curriculum map: threat-model a real, given LLM feature end to end. You get a fourth scenario — genuinely different from GreenCart (Chapter 1), Waypoint (this chapter's lesson), and ReviewMate (this chapter's exercises) — and no worked answer to check against while you work. Use the seven-step method from this chapter, in order.

AskHR is a fictional internal HR chatbot deployed inside a company-wide Slack workspace. Employees message it — one-on-one, or in small HR-support group channels that sometimes include more than one employee at once — to ask policy questions, look up their own HR information, and request routine actions.

askhr_tools.md (internal engineering doc) 
AskHR assistant -- tool inventory (as shipped)

search_hr_policies(query)
  -> semantic search over a vector store indexed from (a) the
     company's own internal HR policy documents and (b) a licensed
     third-party compliance-content feed (labor-law summaries,
     updated automatically on a schedule), mixed together with no
     per-source tag carried through to query time.

get_employee_record(employee_id)
  -> returns an employee's full HR record: role, manager, PTO
     balance, salary band, and any leave-related notes on file
     (which can include sensitive medical/caregiving context).
     Callable with ANY employee_id -- not scoped to "yourself or
     your direct reports."

initiate_leave_request(employee_id, leave_type, start_date, end_date)
  -> creates a leave request and auto-approves it immediately if the
     requested duration is under a threshold AskHR's system prompt
     states in plain text. No identity re-verification step, no
     per-request cap tied to the employee's actual PTO balance.

escalate_to_hr_specialist(employee_id, note, priority)
  -> opens a ticket for a human HR specialist. The ticket body is
     built by inserting AskHR's generated note directly into the
     ticketing system's HTML template, unescaped.

Session model: every Slack message in a thread -- including all
employees present in a shared group channel -- is concatenated with
AskHR's system prompt into one context window before each model
call, and every tool's return value is appended to that same context
for the rest of the session. The system prompt states the exact
auto-approval leave-duration threshold, and separately, a list of
keywords that trigger an automatic emergency escalation.

Your task

Download starter.py and fill in its three parts, applying the seven-step method from the lesson in order:

1 Tool inventory (Step 1)

Every tool, its real side effect, and its blast radius.

2 Context-source inventory + trust classification (Steps 2–3)

Every source of text that reaches AskHR's context window, who controls it, and whether it re-enters context on later turns — including tool outputs, this chapter's core teaching point.

3 The full threat-model table (Steps 4–7)

Real findings, each with an OWASP category, a justified likelihood/impact sentence, and an architectural mitigation. Aim to explicitly consider all 10 OWASP categories (Step 6), even where some end up "not applicable, because...".

How to run this Download starter.py, fill in all three TODO sections, then run python3 starter.py. This project is open-ended — the validator checks structural completeness (enough tools/sources enumerated, trust classified, at least one tool-output re-entry flagged, enough distinct categories covered with real reasoning and a real mitigation), not your exact wording against a hidden key.
starter.py solution.py (reference)

What "done" looks like

A clean structural pass from the validator means your artifact has the right shape: enough enumerated tools and context sources, a trust classification for each, at least one flagged tool-output re-entry, and a threat-model table spanning enough distinct OWASP categories with real justified reasoning and a real mitigation per row. It does not certify that every individual finding is the single best one — this is an open-ended project. Once you're satisfied, compare against solution.py, a complete reference threat model covering all 10 OWASP categories. If your asset list differs significantly, revisit Step 5 (tool outputs re-entering context) and Step 6 (the full ten-category walk) — those are exactly the two steps this chapter's Mistakes 1 and 2 are built around.
