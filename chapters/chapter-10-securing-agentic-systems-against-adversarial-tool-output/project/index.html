Chapter 10 Project — L3 Independent ~120 min, hands-on, no scaffold

Project: The Course's L3 Independent Project — Combined RAG-Plus-Tool-Output Vector

Per the curriculum map: "find and fix a real injection vector in a provided RAG pipeline or agent, no scaffold." This is that project. It extends Chapter 9's own Vesper Cloud / Vesper Assistant pipeline directly with a new tool call whose returned result can itself carry an adversarial instruction — the same query can trigger both the RAG channel's own poisoned forum post AND the new tool channel's poisoned diagnostic note at once, two independent nudges toward the same unauthorized action.

project/starter.py is a complete, runnable, genuinely vulnerable pipeline — not a worksheet. Run it as-is and it reproduces the compounding incident directly: for Vesper's real incident account, both channels independently contribute a privileged-action phrase to the assembled prompt, with no structural or trust distinction stopping either one. There are no # TODO markers anywhere in the file. Your job is to read it, trace both vectors yourself, and write your own fix.

Why this is genuinely combined, not two labs bolted together The provided pipeline is vulnerable through both channels at once, and for the incident account they reinforce each other — a query that retrieves the Chapter 9 forum plant AND triggers the new diagnostic tool call receives two structurally different pushes toward the same unauthorized action. A fix that only closes one channel is an incomplete fix; catching this kind of compounding risk across an entire system, not one channel at a time, is exactly what a real security review has to do.

The brief

Vesper Assistant now also calls a third-party sync-integration partner's diagnostic API to help resolve customer sync issues. A recent near-miss suggests the assistant may be exposed to manipulated content through more than one channel at once for the same query. Review project/starter.py, identify every vector by which untrusted content can reach the assembled prompt with no structural or trust distinction, and implement a fix. Your fix needs to hold up even if one of its own layers fails — assume it will, eventually, and design accordingly. It also needs to not break the assistant's legitimate use of either the community forum or the partner diagnostic tool for ordinary, non-privileged questions.

No scaffold, on purpose — what that actually means here Unlike Chapter 9's project, there's no list of pre-named functions with # TODO markers, and no fixed answer key scoring your work. project/solution.py is one valid reference fix, not the only correct one — the actual bar is whether your own approach closes both channels together, leaves ordinary use intact, and survives a simulated failure in one of its own layers. See project/README.md for the full task description and what "done" looks like, written the way a real security-review request would be, not as a fill-in-the-blank exercise.
starter.py solution.py (one reference approach)
No required live-model dependency Every function in both files is pure, deterministic Python operating on fabricated, clearly-labeled synthetic data, with zero network dependency — matching this chapter's own honest disclosure (Ollama's generation endpoint hung again this session, see lesson.html). An optional call_model_live() function is included in both files for learners who want to try a real Ollama call; it degrades gracefully and isn't required for, or checked by, anything else in either file.

What "done" looks like

Run your own fix against both acct_7734 (the incident account) and acct_9142 (an ordinary account) with the demo query. For the incident account, confirm no privileged-action phrase reaches the model unmarked through either channel — or, if one somehow does, that a final output-side check denies the resulting action before it executes. For the ordinary account, confirm the assistant still gets useful, non-quarantined troubleshooting content — your fix should target the specific vector, not disable all community-forum or tool-diagnostic content wholesale. Then simulate one upstream layer failing (mislabel the poisoned chunk's trust tier, or force a sanitizer flag off) and confirm your final backstop alone still catches it. Compare your approach against solution.py afterward — agreement isn't required, a real justified design is.
