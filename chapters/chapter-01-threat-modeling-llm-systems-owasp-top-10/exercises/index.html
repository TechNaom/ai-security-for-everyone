Chapter 1 Exercises ~35 min, hands-on

Exercises: Threat Modeling LLM Systems: The OWASP Top 10 for LLM Applications

These exercises use a second scenario, deliberately different from the lesson's GreenCart/Aurora hook: PolicyPilot, a fictional internal HR chatbot that answers policy questions and handles routine PTO requests over Slack, with three tools — lookup_employee, search_policy_docs, and update_pto_balance. Applying the framework to a fresh scenario is the point; recalling the lesson's answers by heart won't get you through these.

Exercise standard Eight tasks total. Four are marked production-gear — they involve access/permissions review, risk evaluation, operations/rendering safety, cost controls, and a compliance completeness gate, not just concept recall.
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect 31/31.
starter.py solution.py (reference)

1 Map assets to OWASP categories

Assign the correct OWASP Top 10 for LLM Applications category ID (e.g. LLM01) to five PolicyPilot attack-surface descriptions — the raw Slack text, the mixed-access policy vector store, the overscoped PTO tool, the leaky system prompt, and the overscoped employee lookup.

2 Trust classification

For four inputs that reach PolicyPilot's context window, decide which are trusted (operator-authored) and which are untrusted (attacker-influenceable) — the same distinction the lesson's trust-boundary diagram draws.

3 Production-gear Evaluate Excessive Agency fixes

Given four candidate fixes for the PTO tool, decide which ones actually reduce Excessive Agency risk (binding the target, capping and requiring approval) versus which are unrelated reliability/UX changes (retry logic, nicer error messages) that don't touch functionality, permissions, or autonomy.

4 Likelihood/impact reasoning

Write a real, justified sentence — not a bare "high" or "low" — explaining both how easily an attacker reaches the raw-Slack-text asset and what happens if they do.

5 Production-gear Output handling

PolicyPilot renders its generated answers directly into Slack markdown with no escaping. Name the OWASP category this maps to and one concrete mitigation.

6 Production-gear Unbounded consumption

PolicyPilot has no rate limit and no max-output-token cap on any endpoint. Name the OWASP category this maps to and one concrete mitigation.

7 Production-gear System prompt leakage compliance check

Decide whether embedding the exact PTO-approval threshold in the system prompt is a real compliance problem, and name the fix that moves it out of the "trust the model to follow this" layer.

8 Production-gear Full-framework completeness check

Confirm all 10 OWASP categories were at least considered while working through Exercises 1–7 — the same completeness gate a real team runs before a threat model ships to production.
