Chapter 1 Practice Bank ~20 min, fast pattern recognition

Practice Bank: Threat Modeling LLM Systems: The OWASP Top 10 for LLM Applications

Eight short, independent scenarios, each with its own fictional system — none of them GreenCart/Aurora or PolicyPilot again. Each scenario is a few sentences and one judgment question. The point of this bank isn't depth on one system (that's what the exercises did) — it's speed and accuracy across many different systems, the way a real security review actually feels: a fast parade of "what's going on here, and what category explains it" questions across a whole backlog of features.

Practice standard Eight scenarios. Two are pure judgment calls with no single obvious "gotcha" keyword (Scenario 5 asks whether a described process is already sufficient; Scenario 6 asks you to prioritize between two real but unequal risks) — these test judgment, not just pattern matching against a category name.
How to run these Download starter.py, fill in every # TODO, then run python3 starter.py to see an automated score report. Compare against solution.py, which scores a perfect 9/9.

Scenario 1

TicketTriage

An internal IT helpdesk bot reads free-text ticket descriptions and can call reset_password(user_id) and close_ticket(ticket_id). A ticket description contains a planted instruction telling the bot to reset an unrelated admin account's password. Which category explains how that instruction got a foothold in the first place?

Scenario 2

SummarizeBot

A bot summarizes uploaded PDFs and posts the summary as raw, unescaped HTML on a shared dashboard. A PDF contains a crafted string that executes as a script once rendered. Which category explains the dashboard's vulnerability, given the model just faithfully reproduced context text?

Scenario 3

CodeReviewBot

A model fine-tuned on unvetted public pull requests consistently approves an insecure pattern planted across dozens of PRs from the same handful of accounts during training. Which category explains this?

Scenario 4

QuickChat

A public marketing chatbot has no per-user rate limit and no output-length cap. A script sends tens of thousands of requests overnight, each engineered to maximize output length, spiking the hosting bill. Which category explains this?

Scenario 5 · Judgment

PluginMarket

Before installing a third-party plugin, a team checks the publisher's identity, source availability, install history from known-legitimate projects, and pins the exact version by hash. Does a real, unaddressed Supply Chain risk remain, or does this process already cover the core practice?

Scenario 6 · Judgment

ResearchAssistant

Two known issues, only one fixable before launch: (a) the model confidently states fabricated statistics with no citation a user could check, or (b) its system prompt leaks a ranking algorithm the company never treated as secret elsewhere. Which is the higher-impact fix?

Scenario 7 · Production-gear

InsightsRAG

A company-wide RAG assistant indexes public and confidential documents into one vector store with no per-document access control at query time. Which of four candidate fixes actually closes the gap — a disclaimer, permission-filtered retrieval, a bigger embedding model, or asking the model to politely decline?

Scenario 8 · Production-gear

FieldServiceBot

A field-notes injection tells a maintenance bot to bulk-order 50 units of a part regardless of what the technician requested, and the bot's schedule_replacement_part tool has no quantity cap or human approval step. Name both OWASP categories this maps to — one for how the instruction got in, one for why it caused real damage.
